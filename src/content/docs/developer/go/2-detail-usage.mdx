## 返回類型速查

`sdk` 包直接導出以下類型（均為 miru-core 內部類型的別名，跨 Scriggo/宿主邊界可安全傳遞）：

| 類型 | 用途 |
| :- | :- |
| `sdk.ExtensionListItem` | 列表項：`Title` / `URL` / `Cover` / `Update` / `Image` / `Type` / `Headers` |
| `sdk.ExtensionDetail` | 詳情：`Title` / `URL` / `Cover` / `Desc` / `Description` / `Chapters []ExtensionEpisodeGroup` / `Headers`（`Desc` 與 `Description` 二選一即可） |
| `sdk.ExtensionEpisodeGroup` | 詳情內的章節分組：`Title` + `URLs []string` |
| `sdk.ExtensionWatch` | `Watch` 通用返回：分組鏡像列表 `Groups []ExtensionMirrorGroup` |
| `sdk.ExtensionMirrorGroup` / `sdk.ExtensionMirror` | 鏡像分組 / 單個鏡像：`Name` / `URL` / `Headers` |
| `sdk.ExtensionAllMirror` | `@type all` 的 `Watch` 返回：`Manga` / `Fikushon` / `Bangumi` 三個成員 |
| `sdk.ExtensionMangaWatchMirror` | 漫畫：`URLs []string` + `Headers` |
| `sdk.ExtensionFikushonWatchMirror` | 小說：`Content []string` + `Title` + `Subtitle` |
| `sdk.ExtensionBangumiWatchMirror` | 動畫：`Type`（hls/mp4/torrent/magnet）/ `URL` / `Subtitles` / `Headers` / `AudioTrack` / `TLSConfig` |
| `sdk.ExtensionBangumiWatchMirrorSubtitle` | 字幕：`Language` / `Title` / `URL` |
| `sdk.TLSConfig` | 瀏覽器指紋請求配置：`Profile` / `UserAgent` / `DisableRedirect` / `InsecureSkipVerify` |

內容類型常量：`sdk.HLS`、`sdk.MP4`、`sdk.Magnet`（注意沒有 `sdk.Torrent` 常量——torrent 的內容類型字符串是 `"torrent"`，URL 直接帶原始 `.torrent` 連結或 `magnet:` URI）。

## 網絡請求與緩存

```go
// 發起 HTTP 請求，返回 響應體 / 狀態碼 / 錯誤信息
body, status, errStr := sdk.Fetch("https://example.com/api", "GET", map[string]string{
    "User-Agent": "Miru",
}, "", nil)

// 瀏覽器指紋（tls-client）請求，繞過 Cloudflare 等
body, _, _ = sdk.Fetch(url, "GET", headers, "", &sdk.TLSConfig{Profile: "chrome_133"})

// 將鏡像結構體設置 `TLSConfig`，後端自動改寫所有 URL 為代理地址。
// Torrent / Magnet URL 不需要 TLS 指紋偽裝，直接返回原始鏈接即可。

// 跨函數保存狀態（每個請求都會重新編譯運行一個 Scriggo VM）
sdk.SaveCache("key", value)
v, ok := sdk.GetCache("key")
```

## TLS 指紋偽裝與代理

許多影片串流網站使用 Cloudflare 或類似的反爬蟲服務，會拒絕 Go 預設的 TLS 指紋。
miru-core 使用 **tls-client** 解決此問題——這是一個能模仿真實瀏覽器 TLS 握手
（JA3、HTTP/2 設定等）的函式庫。Go 插件的所有網絡請求都經過後端——Flutter
客戶端永遠不會直接連接上游 CDN。

### 問題

Go 的 `net/http` 會產生一個獨特的 TLS 指紋，Cloudflare 和其他 CDN 能立即識別並封鎖。
爬取這些網站的插件需要一種方式，使請求看起來像是來自真實的 Chrome 瀏覽器。

### 使用 `TLSConfig`

`TLSConfig` 可用於兩種不同的場景——它們**不是**可互換的替代方案，而是各自服務於不同的目的：

| 場景 | 用途 | 運作方式 |
| :-- | :-- | :-- |
| **設置在鏡像上**（`ExtensionBangumiWatchMirror.TLSConfig`） | 代理影片播放串流 | 後端將鏡像中**所有** URL（主 URL + 字幕 URL）改寫為 localhost 代理 URL。Flutter 播放器通過後端獲取，後端使用 tls-client 連接上游。 |
| **搭配 `sdk.Fetch`** | 在 `Detail()` / `Search()` 中發起 HTTP 請求 | 後端執行一次帶有指定 TLS 指紋的伺服器端請求，直接將響應體返回給你的代碼。 |

:::caution[鏡像內的所有 URL 都是原始未代理的]
從 `Mirror()` 返回鏡像時，始終提供**原始上游 URL**。
如果需要 TLS 指紋偽裝，請在鏡像結構體上設置 `TLSConfig`
欄位，後端會自動處理代理。
:::

### 代理 URL 的運作方式

當後端改寫 URL（通過鏡像上的 `TLSConfig`）時，它會產生一個
主機相對的代理 URL，例如：

```
http://127.0.0.1:3000/proxy/video.m3u8?__u=<base64-encoded-raw-url>&__h=<base64-encoded-headers>
```

Flutter 影片播放器請求這個 localhost URL。後端：
1. 從查詢參數解碼原始 URL 和 headers
2. 使用帶有指定指紋的 tls-client 抓取上游資源
3. 將響應串流回播放器

這意味著 Flutter 客戶端**永遠**不會直接與上游 CDN 通訊——所有 TLS 指紋偽裝、CORS
和防盜鏈問題都在伺服器端處理。

### 何時不使用 TLS 指紋偽裝

- **Torrent / Magnet URL**：對於 `type: "torrent"` 或 `type: "magnet"`，
  URL 承載的是原始 `.torrent` 鏈接或 `magnet:` URI。**不要**在這些鏡像上設置
  `TLSConfig`——Torrent 解析由前端或後端獨立端點處理，而非鏡像代理。

## 在 Scriggo 中使用 sdk 包（實戰）

下面把上面列出的 `sdk` API 放進真實的入口函數裡。`sdk` 包在 Scriggo VM 啟動時已注入，直接 `import` 後調用即可。

### Fetch + TLSConfig（詳情頁抓取）

```go
import sdk "github.com/miru-project/miru-core/pkg/extension/golang/sdk"

func Detail(pkg, url string) (*sdk.ExtensionDetail, error) {
    // 普通請求：body 為響應體字符串，status 為狀態碼，errStr 為錯誤信息
    body, status, errStr := sdk.Fetch(url, "GET", map[string]string{
        "User-Agent": "Mozilla/5.0",
        "Referer":    "https://example.com/",
    }, "", nil)
    if errStr != "" {
        return nil, fmt.Errorf("fetch failed (status %d): %s", status, errStr)
    }

    // 需要繞過 Cloudflare / 指紋校驗時，加 TLSConfig
    body, _, _ = sdk.Fetch(url, "GET", headers, "", &sdk.TLSConfig{
        Profile:           "chrome_133",
        InsecureSkipVerify: true,
    })

    // 防盜鏈/跨域的媒體地址：直接使用 URL（帶 TLSConfig 的鏡像會自動代理）

    return &sdk.ExtensionDetail{
        Title:   "示例",
        Cover:   "https://example.com/cover.jpg",
        Desc:    body,
        Chapters: []sdk.ExtensionEpisodeGroup{
            {Title: "第 1 話", URLs: []string{"https://cdn.example.com/a.m3u8"}},
        },
    }, nil
}
```

### Torrent / Magnet 鏡像（原始 URL 直接傳回）

Torrent 或 magnet 內容時，擴展只需返回原始 `.torrent` 連結或 `magnet:` URI，無需解析——前端會自行處理。

```go
func Mirror(pkg, url string) (*sdk.ExtensionBangumiWatchMirror, error) {
    // Torrent 文件地址——直接傳回
    return &sdk.ExtensionBangumiWatchMirror{
        Type: sdk.HLS, // 或原始字符串 "torrent" / "magnet"
        URL:  "https://example.com/files/ep1.torrent",
    }, nil

    // Magnet 連結
    return &sdk.ExtensionBangumiWatchMirror{
        Type: sdk.Magnet,
        URL:  "magnet:?xt=urn:btih:abc123def456&dn=One+Piece+EP1",
    }, nil
}
```


### 在 Mirror 上設置 TLSConfig（自動代理 + TLS 指紋）

對於需要 TLS 指紋偽裝的 HLS/MP4 流（如 Cloudflare 前置的 CDN），在鏡像結構體上設置 `TLSConfig`。後端會自動將所有 URL 改寫為代理 URL：

```go
func Mirror(pkg, url string) (*sdk.ExtensionBangumiWatchMirror, error) {
    // 後端會用 chrome_133 指紋自動代理此 URL
    return &sdk.ExtensionBangumiWatchMirror{
        Type: sdk.HLS,
        URL:  "https://cdn.example.com/video.m3u8",
        Headers: map[string]string{
            "Referer": "https://example.com/",
        },
        TLSConfig: &sdk.TLSConfig{
            Profile: "chrome_133", // 後端自動改寫所有 URL 為 /proxy/ 路徑
        },
        Subtitles: []sdk.ExtensionBangumiWatchMirrorSubtitle{
            {Language: "en", Title: "English", URL: "https://cdn.example.com/subs/en.vtt"},
        },
    }, nil
}
```

Flutter 客戶端收到的代理 URL 形如 `http://127.0.0.1:3000/proxy/video.m3u8?__u=<encoded>`，視頻播放器只與 localhost 通信——所有代理和 TLS 指紋偽裝由後端處理。

### SaveCache / GetCache（跨函數保存狀態）

```go
func Search(pkg, kw string, page int, filter string) ([]sdk.ExtensionListItem, error) {
    token, ok := sdk.GetCache("token")
    if !ok {
        // 首次請求登錄拿 token，存起來供後續調用複用
        body, _, _ := sdk.Fetch("https://example.com/login", "POST", nil, "", nil)
        token = body // 實際應解析出 token
        sdk.SaveCache("token", token)
    }
    body, _, _ := sdk.Fetch("https://example.com/search?kw="+kw, "GET",
        map[string]string{"Authorization": token}, "", nil)
    // ...解析 body 為 []sdk.ExtensionListItem
    return nil, nil
}
```

:::tip
Scriggo VM 每次調用入口函數都會重新編譯運行，函數內局部變量不會跨調用保留；需要複用的數據（token、cookie 等）一律用 `sdk.SaveCache` / `sdk.GetCache`（值為 `string`）保存。
:::

## 完整示例

```go
// ==MiruExtension==
// @name         Example
// @version      v0.1.0
// @author       Miru
// @license      MIT
// @lang         all
// @icon         https://example.com/icon.png
// @package      example
// @type         all
// @webSite      https://example.com
// ==/MiruExtension==

package example

import sdk "github.com/miru-project/miru-core/pkg/extension/golang/sdk"

func Search(pkg, kw string, page int, filter string) ([]sdk.ExtensionListItem, error) {
    return []sdk.ExtensionListItem{
        {Title: "示例 1", URL: "https://example.com/1", Cover: "https://example.com/1.jpg", Type: "manga"},
    }, nil
}

func Latest(pkg string, page int) ([]sdk.ExtensionListItem, error) {
    return []sdk.ExtensionListItem{
        {Title: "最新 1", URL: "https://example.com/latest/1", Cover: "https://example.com/latest/1.jpg", Type: "manga"},
    }, nil
}

func Detail(pkg, url string) (*sdk.ExtensionDetail, error) {
    return &sdk.ExtensionDetail{Title: "詳情", Desc: "描述", URL: url}, nil
}

func Watch(pkg, url string) (*sdk.ExtensionAllMirror, error) {
    return &sdk.ExtensionAllMirror{
        Manga: &sdk.ExtensionMangaWatchMirror{URLs: []string{"https://example.com/1.jpg"}},
        Fikushon: &sdk.ExtensionFikushonWatchMirror{
            Title:   "第 1 章",
            Content: []string{"第一段。", "第二段。"},
        },
        Bangumi: &sdk.ExtensionBangumiWatchMirror{Type: sdk.HLS, URL: url},
    }, nil
}

// Mirror 解析用戶所選的鏡像，返回最終的按類型播放結構
func Mirror(pkg, url string) (*sdk.ExtensionBangumiWatchMirror, error) {
    return &sdk.ExtensionBangumiWatchMirror{Type: sdk.HLS, URL: url}, nil
}
```

## Scriggo 的限制

Miru 的 Go 插件由 [Scriggo](https://scriggo.com/limitations) 引擎編譯運行，它並非完整的 Go 編譯器，而是為「在 Go 中嵌入腳本」設計的解釋器。編寫插件時需要注意以下限制（完整列表見 Scriggo 官方文檔）：

### 尚未支持、仍在開發中的特性

- **方法聲明（method declarations）**：無法為類型定義方法，只能寫包級函數。
- **接口類型定義（interface types）**：不能 `type X interface { ... }` 自行定義接口。
- **`for range` 中賦值給非變量**：例如 `for i, (&s).field = range ...` 不被支持。
- **導入 `unsafe` / `runtime` 包**：Scriggo 中無法 `import "unsafe"` 或 `import "runtime"`。
- **帶標籤的 `continue` / `break`**：不支持 `label:` 形式的跳轉。
- **未導入就編譯非 main 包**：一個插件文件通常是一個獨立的包，無法直接 `import` 並編譯另一個插件包。

### 與 Go 官方編譯器 `gc` 互操作帶來的限制

- **`reflect` 無法正確識別 Scriggo 內定義的類型**：例如 `fmt.Printf("%T", v)` 中 `v` 是 Scriggo 定義的類型時，打印出的會是它被包裝前的底層類型名，而非你定義的類型名。
- **Scriggo 定義的結構體中的非導出字段仍可被原生包的 `reflect` 訪問**：這些字段帶有特殊前綴以避免被意外訪問，但無法通過 `reflect` 修改。
- **結構體嵌入**：除接口外，若嵌入的類型帶有方法，則它必須是結構體的**第一個字段**（受 `reflect.StructOf` 限制）。
- **`select` 最多 65536 個 case**。
- **原生包必須在 `packages.go` 中導出才能導入**：只有 miru-core 後端已經使用並導出的包可用，無法在插件裡隨意引入任意第三方包。
- **類型不會被垃圾回收**（見 golang/go#28783），長時間運行的宿主中應注意不要無限累積類型。

### 性能取向的硬性限制

為提升解釋執行性能，Scriggo 對每個函數施加了上限（超出會編譯失敗）：

| 限制項 | 上限 |
| :-: | :-: |
| 單函數的整數 / 浮點 / 字符串 / 通用寄存器 | 各 127 個 |
| 函數字面量聲明 + 唯一函數調用 | 256 個 |
| 可用類型數 | 256 個 |
| 唯一預定義函數數 | 256 個 |
| 整數 / 浮點常量值 | 各 16384 個 |
| 字符串常量值 | 256 個 |
| 通用值 | 256 個 |

### 對插件編寫的實操建議

- **只用包級函數與結構體**：不要嘗試定義方法或接口類型；把邏輯寫成普通 `func`。
- **避免依賴 `reflect` / `fmt %T`**：讀取返回結構時直接用 SDK 提供的類型，不要用反射去識別自定義類型。
- **控制單文件複雜度**：不要在一個函數裡塞入巨量常量、類型或閉包，必要時拆分成多個入口函數。
- **不要依賴 `unsafe` / `runtime`**：網絡與代理能力請統一走 `sdk.Fetch` / 鏡像上的 `TLSConfig`，而非底層包。
- **狀態用 `sdk.SaveCache` 而非全局變量**：每個請求都會重新編譯運行一個 Scriggo VM，包級全局變量不會在多次調用間保留。

## 可導入的包

Scriggo 插件只能 `import` **miru-core 後端已經使用並導出**在 [`pkg/extension/golang/packages.go`](https://github.com/miru-project/miru-core/blob/main/pkg/extension/golang/packages.go) 裡的包。這是因為 Scriggo 需要原生 Go 包被編譯進宿主二進制文件——插件無法引入不屬於 miru-core 的包。

當前導出的包主要包含：

- 標準庫：`fmt`、`strings`、`strconv`、`regexp`、`encoding/json`、`encoding/xml`、`encoding/base64`、`net/http`、`net/url`、`crypto/*`、`math`、`time`、`io`、`os`、`sync`、`reflect`、`sort`、`context`、`bufio`、`bytes`、`path/filepath`、`html`、`image` 等（完整列表以源碼為準）。
- 內置的 miru 包：
  - `github.com/miru-project/miru-core/pkg/extension/golang/sdk` —— 插件開發 SDK（請求、緩存等）。
  - `github.com/miru-project/miru-core/pkg/extension/golang/runtime` —— 運行時輔助。
- miru-core 已依賴的第三方包：`github.com/bogdanfinn/tls-client`（瀏覽器指紋請求）、`github.com/PuerkitoBio/goquery`（HTML 解析）、`structs` 等。

:::note
**不能在插件裡隨意引入任意第三方包**。例如 `import "github.com/some/random/pkg"` 會因為該包不屬於 miru-core 後端、未在 `packages.go` 導出而編譯失敗；`unsafe` / `runtime` 也在 Scriggo 限制之列（見上文）。

如果你確實需要某個尚未導出的包，請到 [miru-core 倉庫](https://github.com/miru-project/miru-core) **新建一個 Issue** 說明需求（包名、用途、為什麼 SDK 現有能力做不到），由維護者評估後將其加入 miru-core 的依賴並在 `packages.go` 中導出。
:::
