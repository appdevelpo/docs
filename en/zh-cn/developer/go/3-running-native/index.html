原生 Go 运行

This content is not available in your language yet.

Miru 的 Go 扩展同一份源码可以两种阶段驱动。本页讲阶段一 · 原生 Go（开发期）：把扩展当成一个普通的 Go package 来写，从而获得完整的 IDE 支持与单测能力。

关键点：阶段一与阶段二（Scriggo 运行）使用同一份源文件。你在本地用原生 Go 调通的逻辑，运行时会被 Scriggo 原样编译执行，不会出现「本地能跑、装上跑不了」的偏差。运行时如何驱动见 Scriggo 运行。

打印与日志

Section titled “打印与日志”
  • 临时打印用 fmt.Printf("DEBUG kw=%q items=%d\n", kw, len(items))；确认后删除或改用 log。
  • 需要带时间戳/行号：import "log" 后 log.Printf(...)。
  • Scriggo 运行期看不到你的 fmt 输出（那是宿主侧），所以所有要看的输出请在阶段一用 go test 验证。

gopls 与类型检查

Section titled “gopls 与类型检查”
  • gopls 提供补全、跳转、悬停文档；写代码时就能发现类型错误。
  • 提交前跑 go vet ./... 和 go build ./... 做静态检查，避免把 Scriggo 不支持的低级错误（如未使用的变量）带进运行期。

提示

推荐流程：先在阶段一用原生 Go + go test 把每个入口函数的返回结构调对，再把源文件放进 Miru 扩展目录交给阶段二（Scriggo）运行。两个阶段的返回结构完全一致（见 数据格式），所以本地测试通过即代表运行期正确。

miru-core 仓库内的 pkg/extension/golang/extensions/example 就是这种「一份源码、两阶段通用」的范例——它既能被原生 Go 直接 import 调用，也能被 Scriggo 编译运行。
